# Cross Cleaner — загружаемая библиотека (`injector/`)

Та же программа-очиститель, но в виде библиотеки: её можно загрузить в уже
запущенную программу, и по нажатию горячей клавиши (по умолчанию `Delete`)
окно очистителя появится **внутри окна этой программы**.

```
injector/
├── Cargo.toml                 крейт: cdylib (DLL/.so) + rlib + утилита
├── build.rs                   ресурсы и манифест DLL (Windows)
└── src/
    ├── lib.rs                 точка входа: DllMain (Windows) / .init_array (Linux)
    ├── config.rs              настройки через переменные CROSS_CLEANER_*
    ├── hotkey.rs              описание горячей клавиши и коды клавиш
    ├── watcher/               глобальный перехват клавиши
    │   ├── win.rs             WH_KEYBOARD_LL
    │   └── linux.rs           чтение /dev/input/event* (evdev)
    ├── embed.rs               встраивание окна в окно программы (SetParent + WS_CHILD)
    ├── renderer.rs            выбор OpenGL / DirectX 12 / Vulkan
    ├── session.rs             окно на отдельном потоке (winit any_thread + tokio)
    └── bin/injector_cli.rs    утилита: проверка, LD_PRELOAD-запуск
```

## Что происходит после загрузки

1. `DllMain` (Windows) или конструктор `.init_array` (Linux) создаёт один
   маленький поток — на потоке загрузчика ничего больше делать нельзя.
2. Поток читает настройки, регистрирует встроенные очистители и включает
   перехват клавиши.
3. Первое нажатие горячей клавиши создаёт окно на **другом** потоке: у чужой
   программы уже есть свой цикл событий, а winit допускает только один цикл на
   процесс. Окно создаётся скрытым, встраивается в окно программы и только потом
   показывается.
4. Дальше горячая клавиша показывает/скрывает окно, а окно закрывает очистку.

## Окно внутри окна программы

По умолчанию (`CROSS_CLEANER_WINDOW=auto`) окно становится **дочерним окном**
(`SetParent` + `WS_CHILD`) того окна, в котором вы нажали горячую клавишу:

* в панели задач не появляется второе окно — перемещаете окно программы,
  перемещается и очиститель;
* окно обрезается по границам программы и скрывается вместе с ней при
  минимизации;
* при изменении размера окна программы очиститель остаётся внутри;
* перетаскивается мышью за свою строку заголовка (в пределах окна программы).

Если программа рисует сама (игра с DirectX/Vulkan), она может перекрыть
дочернее окно — тогда нужен режим отдельного окна:

```powershell
set CROSS_CLEANER_WINDOW=window
```

| `CROSS_CLEANER_WINDOW` | Что будет                                                  |
|-------------------------|------------------------------------------------------------|
| `auto` (по умолчанию)   | дочернее окно, если окно программы нашлось, иначе своё окно |
| `embedded`              | только дочернее окно                                       |
| `window`                | всегда отдельное окно поверх всего                         |

Дочернее окно — только в Windows. На Linux и macOS окно всегда отдельное.

## Настройки (переменные окружения)

Библиотеку грузит чужая программа, командной строки у неё нет, поэтому все
настройки — через `CROSS_CLEANER_*`. Утилита `cross-clean-injector` выставляет их
сама, из своих ключей.

| Переменная                  | По умолчанию     | Значение                                             |
|-----------------------------|------------------|------------------------------------------------------|
| `CROSS_CLEANER_HOTKEY`      | `delete`         | клавиша, можно с модификаторами: `ctrl+alt+f12`      |
| `CROSS_CLEANER_ACTION`      | `toggle`         | `toggle`, `show` или `clean` (сразу чистит всё)      |
| `CROSS_CLEANER_WINDOW`      | `auto`           | `auto`, `embedded` или `window`                      |
| `CROSS_CLEANER_RENDERER`    | `auto`           | `opengl`, `directx` (DirectX 12) или `vulkan`         |
| `CROSS_CLEANER_SHOW_ON_START` | —              | `1` — показать окно сразу, без горячей клавиши        |
| `CROSS_CLEANER_EXIT_ON_CLOSE` | —               | `1` — закрытие окна завершает сеанс, а не прячет его   |
| `CROSS_CLEANER_DATABASE`    | встроенная       | свой файл базы очистки (JSON)                         |
| `CROSS_CLEANER_REGISTRY_DATABASE` | встроенная | свой файл базы реестра (Windows)                      |
| `CROSS_CLEANER_DISABLE_CUSTOM` | —               | `1` — не использовать встроенные пользовательские очистки |
| `CROSS_CLEANER_DEBOUNCE_MS` | `400`            | пауза между двумя срабатываниями                     |
| `CROSS_CLEANER_AUDIO`       | —                | `1` — открыть звуковое устройство для озвучки кнопок   |
| `CROSS_CLEANER_LOG`         | —                | файл журнала                                          |
| `CROSS_CLEANER_DISABLED`    | —                | `1` — загрузить библиотеку и ничего не запускать      |

Важно: переменные окружения читаются **внутри** той программы, куда загружена
библиотека, поэтому их нужно задать до запуска этой программы.

## Графика

Выбирается один раз при создании окна и не переключается на лету: winit разрешает
создать цикл событий только один раз на процесс.

* `opengl` — обычный OpenGL через `glow`/`glutin`, самый совместимый вариант;
* `directx` — DirectX 12 через wgpu (единственный DirectX-бэкенд у wgpu);
* `vulkan` — Vulkan через wgpu;
* `auto` — OpenGL, затем DirectX 12, затем Vulkan, пропуская то, для чего на
  машине нет адаптера (адаптеры проверяются без создания окна).

Программа, которая сама рисует (игра с DirectX/Vulkan), обычно перекрывает
дочернее окно: для неё помогает `CROSS_CLEANER_WINDOW=window`.

## Сборка

```powershell
# обычная сборка (для отладки)
cargo build -p injector

# то, что нужно загружать в программу: без strip-символов и без abort при панике
cargo build -p injector --profile injected
```

Профиль `injected` отличается от `release` только стратегией паники: библиотека
работает внутри чужого процесса, поэтому паника не должна его завершать
(`panic = "unwind`), а точки входа потоков ловят паники через `catch_unwind`.
Собранный обычным `cargo build --release` вариант об этом предупреждает в
журнале.

Готовые файлы:

```
target/debug/cross_cleaner_injector.dll      (Windows, для отладки)
target/injected/cross_cleaner_injector.dll   (Windows, для загрузки)
target/injected/libcross_cleaner_injector.so (Linux)
target/injected/cross-clean-injector         (Linux)
target/injected/cross-clean-injector.exe     (Windows)
```

## Как загрузить

DLL загружается любым сторонним загрузчиком (Extreme Injector в обычном режиме,
Process Hacker, x64dbg и т. п.). Достаточно указать путь к
`cross_cleaner_injector.dll` и выбрать процесс.

Через утилиту из этой папки — только для проверки, без загрузки в чужой процесс:

```powershell
# окно очистителя в этом же процессе (тот же код, что и в загруженной DLL)
target\injected\cross-clean-injector.exe --standalone

# загрузить библиотеку в этот процесс и подождать 30 секунд
target\injected\cross-clean-injector.exe --library target\injected\cross_cleaner_injector.dll

# проверить, что окно действительно становится дочерним
target\injected\cross-clean-injector.exe --embed-test
```

На Linux библиотека попадает в программу через `LD_PRELOAD`:

```bash
cargo build -p injector --profile injected
target/injected/cross-clean-injector --preload target/injected/libcross_cleaner_injector.so -- some-program
```

Глобальные горячие клавиши на Linux читают `/dev/input/event*`, поэтому нужен
root или членство в группе `input`:

```bash
sudo usermod -aG input "$USER"   # затем выйти из сеанса и войти снова
```

## Ограничения

* 64-битную DLL нельзя загрузить в 32-битную программу и наоборот.
* Библиотеку нельзя выгружать обратно (`FreeLibrary`, `dlclose`), пока она
  работает: её потоки остаются внутри её кода. Пусть программа завершится сама.
* После закрытия окна программы встроенное окно тоже исчезает, и горячая клавиша
  его больше не откроет.
* На macOS глобальных горячих клавиш нет: окно открывается только из своей
  программы (`--standalone`).
